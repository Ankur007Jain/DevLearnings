🚨 Exam Gotcha — Dynamic Column Query Order (CRITICAL) When a question involves a dynamic/JSON column, the correct operator order is:

Table | where TimeGenerated > ago(5m) | extend Field = tostring(DynCol.field) | where Field == "value" | project Col1, Col2, Field

Why order matters:
MistakeWhat Goes Wrong
| project before | extendproject drops the dynamic column — extend can't find it anymore → error
| where Field == "x" before | extend Field = ...Field doesn't exist yet — filter fails
Add | count at endReturns a single row with a count — NOT the actual rows the question asks for
Use between(ago(5m) .. now()) instead of > ago(5m)Both work, but > ago(5m) is simpler and preferred in exam answers

Correct pattern for dynamic column queries:
1. | where on native columns (time filter first — always)
2. | extend to extract from dynamic column
3. | where on the newly extended field
4. | project to select final columns (last step)

🔷 Practice Exercises

Read the scenario. Write the KQL query mentally or on paper. Then reveal the solution.

01 Filter events from the last 24 hours with Level = "Error" ▼
Scenario: A KQL database table called AppEvents has columns: Timestamp (datetime), Level (string), Source (string), Message (string). Write a query to return all Error-level events from the last 24 hours.
AppEvents
| where Timestamp > ago(24h)
| where Level == "Error"

Notes: Use ago(24h) for "last 24 hours". String comparisons in KQL are case-sensitive — "Error" ≠ "error". Multiple | where clauses are AND'd together.

02 Count events per Source in the last 7 days ▼
Scenario: Using the same AppEvents table, find how many events each Source generated in the last 7 days. Return top 10 sources by count, highest first.
AppEvents
| where Timestamp > ago(7d)
| summarize EventCount = count() by Source
| top 10 by EventCount desc

Notes: summarize count() by col groups and counts. The result column is named count_ by default, or you can alias with count() as EventCount or EventCount = count().

03 Average temperature per device per hour (time bucketing) ▼
Scenario: Table TelemetryData has columns: EventTime (datetime), DeviceId (string), Temperature (real). Calculate the average temperature per device per 1-hour bucket over the last 48 hours.
TelemetryData
| where EventTime > ago(48h)
| summarize AvgTemp = avg(Temperature) by DeviceId, bin(EventTime, 1h)
| sort by EventTime asc, DeviceId asc

Notes: bin(EventTime, 1h) is the KEY concept — it rounds timestamps down to the nearest 1-hour boundary, creating time buckets. This is the KQL equivalent of a tumbling window aggregation. Heavily tested on the exam.

04 Add a computed column and filter on it ▼
Scenario: Table SalesData has: OrderId, Quantity (int), UnitPrice (real), Region (string). Find all orders where TotalValue (Quantity × UnitPrice) exceeds 1000, and return OrderId, Region, and TotalValue.
SalesData
| extend TotalValue = Quantity * UnitPrice
| where TotalValue > 1000
| project OrderId, Region, TotalValue
| sort by TotalValue desc

Notes: extend adds a new computed column to the result. You can then filter with where on that extended column. project selects only the columns you want in the output.

05 Count distinct users and error events by region ▼
Scenario: Table WebLogs has: Timestamp, UserId, Region, EventType (string: "PageView", "Error", "Purchase"). For the last 30 days, find: distinct user count AND error event count per Region.
WebLogs
| where Timestamp > ago(30d)
| summarize
    UniqueUsers = dcount(UserId),
    ErrorCount = countif(EventType == "Error")
  by Region
| sort by UniqueUsers desc

Notes: dcount() gives approximate distinct count (more efficient than exact count). countif(predicate) counts only rows matching a condition. Multiple aggregations in one summarize: separate with commas.

06 Join two tables to enrich events with device metadata ▼
Scenario: Table Events has: Timestamp, DeviceId, Value. Table Devices has: DeviceId, Location, DeviceType. Return events from the last 24 hours enriched with Location and DeviceType.
Events
| where Timestamp > ago(24h)
| join kind=inner (
    Devices
    | project DeviceId, Location, DeviceType
  ) on DeviceId
| project Timestamp, DeviceId, Value, Location, DeviceType

Notes: KQL join syntax: left table | join kind=TYPE (right table) on JoinKey. The right-side table is in parentheses. kind=inner keeps only matching rows. Use kind=leftouter to keep all events even if the device has no metadata.

07 Query a shortcut (external table) in a KQL database ▼
Scenario: A KQL database has a shortcut named HistoricalSales pointing to an external ADLS Gen2 path (non-accelerated). Write a query to get the count of sales records by Region from this shortcut where Year = 2024.
external_table('HistoricalSales')
| where Year == 2024
| summarize SalesCount = count() by Region
| sort by SalesCount desc

Notes: Shortcuts in a KQL database are queried with external_table('name') — NOT just the table name. This is because non-accelerated shortcuts are external tables. If the shortcut were accelerated, it would behave like a native table and could be queried directly by name.

08 Find events in a specific datetime range ▼
Scenario: Table SecurityLogs has Timestamp and EventType. Find all events between January 1, 2025 and March 31, 2025 (inclusive) where EventType is "LoginFailure". Return count by day.
SecurityLogs
| where Timestamp between (datetime(2025-01-01) .. datetime(2025-03-31))
| where EventType == "LoginFailure"
| summarize FailureCount = count() by bin(Timestamp, 1d)
| sort by Timestamp asc

Notes: between(a .. b) is inclusive on both ends. datetime(2025-01-01) creates a datetime literal. bin(Timestamp, 1d) creates daily buckets. The combination of between + bin for time-range analysis is a common exam pattern.

09 Identify devices with average temperature above threshold ▼
Scenario: Table SensorData has: Timestamp, SensorId, Temperature. Find all sensors where the average temperature in the last 24 hours exceeded 80 degrees. Return SensorId and AvgTemperature, sorted by highest first.
SensorData
| where Timestamp > ago(24h)
| summarize AvgTemperature = avg(Temperature) by SensorId
| where AvgTemperature > 80
| sort by AvgTemperature desc

Notes: You can filter on the result of a summarize by chaining another | where after summarize. This is like a HAVING clause in SQL. The pattern: summarize first → then filter the aggregated result.

10 Full scenario: Multi-step streaming analytics query ▼
Scenario (exam-style): An eventhouse receives real-time IoT events in table DeviceEvents: Timestamp (datetime), DeviceId (string), EventType (string), Value (real), Region (string). Write a query that:
1. Looks at the last 6 hours
2. Counts total events AND error events per Region per 30-minute bucket
3. Adds a computed column ErrorRate = ErrorCount / TotalCount * 100
4. Returns only buckets where ErrorRate > 5%
5. Orders by ErrorRate descending
DeviceEvents
| where Timestamp > ago(6h)
| summarize
    TotalCount = count(),
    ErrorCount = countif(EventType == "Error")
  by Region, bin(Timestamp, 30m)
| extend ErrorRate = toreal(ErrorCount) / TotalCount * 100
| where ErrorRate > 5
| sort by ErrorRate desc

Notes: This combines: time filtering (ago), multi-aggregation (count + countif), time bucketing (bin 30m), computed column (extend), post-aggregation filter (where on ErrorRate). The toreal() cast ensures floating-point division. This type of multi-step query is typical in DP-700 exam scenarios.

11 ⚠️ EXAM Q: Dynamic JSON column — extract, filter, project (correct order) ▼
Scenario (real exam question): A KQL database table RawTelemetry has columns:
• TimeGenerated (datetime)
• Message (string)
• AdditionalContext (dynamic) — contains JSON with Level (int) and DeviceId (string)

Return rows from the last 5 minutes for DeviceId = "device1". Include only TimeGenerated, Message, Level, DeviceId.
RawTelemetry
| where TimeGenerated > ago(5m)
| extend Level = toint(AdditionalContext.Level),
         DeviceId = tostring(AdditionalContext.DeviceId)
| where DeviceId == "device1"
| project TimeGenerated, Message, Level, DeviceId

Why this order is critical:

StepWhy
1. | where TimeGenerated > ago(5m)Filter on native column first — fast, reduces rows
2. | extend Level and DeviceId from AdditionalContextExtract from dynamic column BEFORE filtering or projecting on it
3. | where DeviceId == "device1"Now filter on the extended field — it exists now
4. | project final columnsSelect last — so all needed columns are still available

Common wrong answers:
❌ | project before | extend — drops AdditionalContext, extend fails
❌ | count at end — returns aggregate count, not the rows
❌ | where DeviceId == "device1" before extend — DeviceId doesn't exist yet
