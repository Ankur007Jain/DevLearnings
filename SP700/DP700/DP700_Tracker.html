Scenario Q&A
After deploying a pipeline from Dev to Test, it still points to the Dev database. What's missing?▼

Gotchas
  • Dynamic Data Masking ≠ blocking accessDDM shows masked values (e.g. XXXX-1234 for SSN). Users with UNMASK permission still see the real data. It's obfuscation, not access control.
  • OneLake Data Access Roles are NEW (GA 2025)These are folder/file level within a lakehouse. Separate from item permissions. You create a role, assign paths, assign users. Exam will test this.
  • Workspace logging captures item operationsWho read, modified, or deleted items. Stored in a Log Analytics workspace. NOT the same as pipeline run monitoring.
  • Sensitivity labels can be auto-inheritedIf you label a source dataset as Confidential, any report built from it may inherit that label automatically (depends on tenant policy).
Scenario Q&A
A user can query a warehouse but must only see masked credit card numbers. They should NOT be fully blocked. What do you implement?▼
✓ Dynamic Data Masking on the credit card column. This shows masked values to users without UNMASK permission while still allowing them to query.

✗ Not column-level security — that blocks the column entirely, which would prevent the query from returning results at all.
Users in the Sales team should only see rows where Region = their own region. What do you configure?▼
✓ Row-Level Security (RLS) on the warehouse. Create a security predicate function that filters rows based on the current user's identity, then apply it to the table via a security policy.
A user needs read access to the /Tables/Customers/ folder in a lakehouse but nothing else in the workspace. What's the minimum access required?▼
✓ Two steps:
1. Grant ReadData item permission on that specific lakehouse (not a workspace role)
2. Create an OneLake data access role scoped to /Tables/Customers/ and assign the user

✗ Not a workspace role — Viewer would expose all items in the workspace.
A Confidential sensitivity label is applied to a lakehouse. A data engineer creates a new report from that lakehouse. What label does the report get?▼
✓ Confidential — sensitivity labels propagate downstream. The report inherits the label from the source lakehouse automatically (if the tenant policy allows inheritance).

Scenario Q&A
IoT device events arrive from Event Hub. You need to route them to BOTH a KQL database AND a Lakehouse simultaneously, with no code. What do you use?▼
✓ Eventstream — supports multiple destinations (fan-out) with a no-code UI. Connect Event Hub as source, add KQL Database and Lakehouse as destinations in the same eventstream.
You need to join a streaming data source with a historical batch table and apply complex business logic in Python. What's the right tool?▼
✓ Spark Structured Streaming in a notebook — handles stream-batch joins, custom Python logic, full Spark API. Eventstream can't do stream-batch joins or custom code.
Write a KQL query to get the average temperature per device, grouped into 5-minute buckets, for the last hour.▼
SensorData
| where Timestamp > ago(1h)
| summarize avg(Temperature) by DeviceId, bin(Timestamp, 5m)
| order by Timestamp desc
bin() is the KQL tumbling window. ago(1h) = last 1 hour from now.

Scenario Q&A
A pipeline Copy Activity runs for 2 hours then fails with a timeout error. The source is a large SQL table. What are the two best fixes?▼
✓ 1. Increase the activity timeout in the pipeline activity settings (default is often 7 days but some environments set lower).
✓ 2. Optimize the source query — add WHERE clause to filter only new data (incremental), add indexes on the source table, or enable partition-based parallel copy to split the load.
Data is being ingested into a KQL database but records are missing. The eventstream shows events flowing. Where do you look first?▼
✓ Run: .show ingestion failures in KQL to see dropped records and the reason. Most common causes: schema mismatch (source has new field), wrong data format specified, or mapping error.

Also check: .show table T ingestion mappings to verify the schema mapping is correct.
A Dataflow Gen2 refresh is very slow and times out. The dataflow reads from a SQL source and does several merge steps. What's the likely problem and fix?▼
✓ Query folding is broken — merges placed before filter steps prevent query folding (filter pushdown to SQL source). Fix: restructure Power Query steps so all filter/where steps come BEFORE any merge/join. This pushes the WHERE clause to the SQL source and reduces data pulled into memory.

Scenario Q&A
A lakehouse table has 50,000 small Parquet files after months of streaming ingestion. Queries are slow. What single command fixes this?▼
✓ OPTIMIZE — run OPTIMIZE tablename in a notebook (PySpark) or SQL endpoint. This compacts small files into larger ones, dramatically reducing file overhead for reads. Combine with ZORDER BY on filter columns for maximum benefit.
A Spark notebook joins a 500GB fact table with a 5MB dimension table. The job runs slowly due to shuffle. What's the fix?▼
✓ Broadcast join — hint Spark to broadcast the small dimension table: spark.sql("SELECT /*+ BROADCAST(dim) */ ...") or df.join(broadcast(dim_df), ...). The small table is sent to all executors, eliminating the shuffle on the large table.
